*cubrid.txt*                   CUBRID for Neovim

The plugin uses the shared CUBRID language server for completion and syntax
diagnostics. It never executes SQL. Neovim 0.12.5 is the tested version.

INSTALL                                                    *cubrid-install*

Install the plugin from https://github.com/vimkim/cubrid.nvim. Install the
shared server separately using the guide at
https://github.com/vimkim/cubrid-language-tools/blob/main/docs/install.en.md.
The server must be on Neovim's PATH, or set server_path below. Keyword
completion does not require the native pair. Strict syntax diagnostics need a
qualified parser worker and its matching runtime; neither is bundled.

For LazyVim, add a plugin spec under lua/plugins with lazy = false,
main = "cubrid", and opts = {} so setup registers filetypes at startup.
See the repository README for the complete spec.

COVERAGE AND UPGRADES                                      *cubrid-coverage*

The shared server owns completion, syntax diagnostics, and conservative
CUBRID-A authoring warnings. SHOW and hint suggestions are broader than native
syntax coverage. Correcting an authoring warning can leave unsupported coverage.

Current core coverage is bounded-query-dml-schema-engineer-ordered-v4 for
cubrid-11.5.0.2704-cc94778 on Linux x86-64. The admitted hint form is one
argument-free /*+ ORDERED */ immediately after top-level literal SELECT.
FROM, joins, and other hints remain unsupported in that form. Native SHOW
coverage is only SHOW TRACE. Exact limits are in the core reference:
https://github.com/vimkim/cubrid-language-tools/blob/main/docs/coverage.en.md
SQL formatting and semantic or style linting remain future work.

Upgrade the core and native worker with its matching manifest and qualified
runtime together. Follow the installation guide above. Plugin updates and
just sync do not rebuild the worker. A v3 worker does not supply v4 coverage.
The Python wheel contains no native assets. The --version value 0.1.0.dev0
identifies neither the source commit nor the coverage revision.

Earlier Neovim, Blink, and isolated LazyVim checks used earlier engines. They
are not a new v4 or personal-profile acceptance run. See the evidence scope:
https://github.com/vimkim/cubrid.nvim/blob/main/docs/acceptance.md

SETUP                                                        *cubrid-setup*

Call require('cubrid').setup(options) from trusted user Lua before opening a
file. Each call replaces all previous options. Unknown or invalid options
raise an error and leave the last valid settings in effect.

auto_start        Boolean. Default true enables vim.lsp.config.cubrid through
                  vim.lsp.enable(). false leaves activation to native user or
                  LazyVim configuration. It does not stop an existing client
                  or disable an externally enabled configuration.
server_path       Absolute server executable. Omit to use
                  cubrid-language-server on the editor host's PATH.
file_extensions   Dense list of exact suffixes ".sql" and ".csql". Default
                  { ".sql", ".csql" }; a single suffix selects only that
                  extension, and {} disables both. Matching filenames ignores
                  case. The list replaces the defaults. Reopen existing files
                  after changes. Replace the old sql option with this list.
parser_worker     Absolute path to the qualified native worker.
runtime_prefix    Absolute path to its matching runtime. Set both paths.
                  Omit both to discover the worker and runtime from the
                  selected server installation metadata. The plugin reads
                  native/parser-worker/build/parser-worker and its adjacent
                  manifest.json under the recorded source directory. The
                  manifest supplies runtimePrefix. just sync does not build
                  the worker. Wheel or index installs and removed local builds
                  require explicit native paths.
worker_manifest   Optional absolute manifest path. Requires the native pair.
worker_timeout    Positive seconds up to 300. Requires the native pair.
profile           Nonempty parser profile override.
script_mode       "sql" or "csql".
config_path       Absolute metadata configuration path.
schema_snapshot   Omit to inherit project metadata, use vim.NIL to disable,
                  or set an absolute snapshot path.

The plugin warns about observed conflicting filetypes and attached foreign LSP
clients. It does not change their state. If the server is missing, install it
on Neovim PATH or set server_path, then run :CubridRestart. Missing server
and native prerequisites produce WARN notifications with the GitHub installation
guide and retry steps. Native failures leave keyword completion available while
strict syntax diagnostics are unavailable. Unchanged failures do not repeat
across buffers or settings updates. Repair the paths and run :CubridRestart.
With auto_start=false, these checks wait until the LSP configuration is enabled.

Executable selection comes only from trusted setup or native Lua configuration.
Neovim owns activation and server processes. The default configuration shares
one stable-root client across CUBRID buffers.
The server discovers metadata independently for each file. On Neovim 0.12.5,
an unnamed buffer uses URI file://. The current server searches for its
metadata from the parent of the initialize root, which is the editor current
directory at the first setup or native configuration load.

NATIVE LSP                                                   *cubrid-native*

The package includes lsp/cubrid.lua. nvim-lspconfig and Blink are optional.
For explicit activation, configure the plugin before opening files: >lua
    require('cubrid').setup({ auto_start = false })
    vim.lsp.config('cubrid', {
      cmd = { '/absolute/path/to/cubrid-language-server' },
      settings = { cubrid = { schemaSnapshot = vim.NIL } },
    })
    vim.lsp.enable('cubrid')
<
Without setup(), native enable also works for buffers whose filetype is already
cubrid. Supply your own detection or use :setfiletype cubrid. Calling native
enable after ordinary setup reuses the same default client. To stop clients
and disable automatic activation, call vim.lsp.enable('cubrid', false).

Native cmd, capabilities, on_attach, and settings overrides work before or
after setup(). Set them before activation. Existing clients require
:CubridRestart after native config changes. Neovim merges global '*' options,
runtime configuration, then server-specific vim.lsp.config('cubrid', ...) values.
Later native config calls merge into earlier calls. settings.cubrid overrides
matching setup options. setup() replaces its own options completely and keeps
native overrides. Initialization and configuration updates send complete
effective settings. Changes during startup apply when initialization completes.

before_init prepares those settings. on_exit reports failed sessions. If you
replace either callback, chain the shipped callback. Manual completion uses
LspAttach and LspDetach independently of your on_attach callback.

The default root remains fixed when the working directory changes. A native
root_dir override can create separate clients per root. With multiple clients,
:CubridReloadSchema uses the current buffer's client. :CubridRestart restarts
all CUBRID clients. User root callbacks retain native asynchronous attachment.

For LazyVim, load this local plugin with lazy=false and
opts={auto_start=false}. Add servers.cubrid={mason=false} to LazyVim's
neovim/nvim-lspconfig opts. Put native overrides under servers.cubrid. LazyVim
then configures and enables the server through the native manager. Do not add
a manual vim.lsp.start() call. The READMEs contain the complete plugin spec.
Blink uses its ordinary lsp source. Outside LazyVim, Blink users may pass
require('blink.cmp').get_lsp_capabilities() as native capabilities.

The plugin suite tests Linux with Neovim 0.12.5. Earlier versions and full
LazyVim distribution startup are unverified. A custom cmd RPC function can
start a client, but doctor cannot infer its transport or executable. A command
argv list allows doctor to probe the selected command.

COMPLETION                                                *cubrid-completion*

In Insert mode, press CTRL-X CTRL-O, select with CTRL-N, and accept with
CTRL-Y. CTRL-Y applies the full supported edit, including text after the
cursor. CTRL-E cancels. Space or Escape can discard the menu while leaving a
native preview suffix in the buffer. The plugin owns the buffer-local
omnifunc while its CUBRID client is attached. On detach it restores the previous value only if
the value still belongs to the plugin. Other completion clients keep their
own handlers. The menu uses CUBRID server results only.

The adapter supports plain, single-line text edits whose range contains the
request cursor. Multiline edits, snippets, insert/replace edits, commands,
additional edits, and items requiring resolution are reported as unsupported.
For example, an unclosed quoted identifier at the end of a file can return a
multiline edit. The adapter does not show a partial menu for such a response.
If the buffer changes while a request is pending, the response is discarded.
If an edit invalidates a visible menu, the plugin cancels it and reports the
cancellation. A stale refusal after native insertion preserves the current
buffer text and does not claim that the server edit was applied.

:CubridReloadSchema                                       *:CubridReloadSchema*
    Reload snapshots and report availability and stale state per document.
    A failed reload retains the last valid metadata.

:CubridDoctor                                                   *:CubridDoctor*
    Report the selected installation, active client, diagnostics, and LSP
    log. Run a private syntax diagnostic probe with a fixed SQL document.
    :checkhealth cubrid shows the same report. The Lua function
    require('cubrid').doctor() returns a report table for headless use.

:CubridRestart                                                 *:CubridRestart*
    Stop CUBRID clients and enable the native configuration again. Use this
    command to retry a missing or failed server. A changed server_path also
    restarts an enabled configuration.

A server with SHOW/hint support supplies SHOW commands, optimizer hints, and
CUBRID-A authoring warnings. The plugin forwards these results without a
local parser. Correcting an authoring warning can leave unsupported coverage
unchanged.

The native server reports unsupported coverage and runtime failures as
diagnostics. An empty diagnostic list does not certify all SQL. Highlighting
and indentation are lexical and do not format or validate SQL.
